# Hyperliquid signing parity fixtures

The committed vectors were generated from the official Hyperliquid Python SDK
tag `0.24.0`, commit
`2fdb18f9517675ea03695a0962bd19eece9c83f0`.

`generate.py` refuses any other checkout revision. It derives a deterministic,
test-only signer scalar in memory from the public label recorded in the JSON.
The generator emits only byte lengths, cryptographic digests, public addresses,
domains, and action hashes. For every L1 vector it digests the upstream
`msgpack.packb` bytes, `action_hash` output, EIP-712 message hash, and signature;
for `approveAgent` it digests the `sign_agent` / `user_signed_payload` EIP-712
message and signature. It never emits a private scalar, raw signature,
MessagePack preimage, or complete signed exchange body.

Python SDK parity covers action MessagePack encoding, the L1 action hash,
phantom-agent EIP-712 data, and `approveAgent` EIP-712 fields. The named-agent
expiry suffix is not generated by Python SDK 0.24.0; its separate provenance is
the TypeScript protocol implementation pinned at commit
`db80d598f6e4672edc090fe69994ecec97ebc980`:
https://github.com/nktkas/hyperliquid/blob/db80d598f6e4672edc090fe69994ecec97ebc980/src/api/exchange/_methods/approveAgent.ts

The mainnet vectors are encode-only regression evidence. Production signing
entry points in this package reject mainnet before invoking an injected signer,
and this fixture generator has no transport or submission path.

Generate to stdout from a clean pinned checkout:

```sh
PYTHONPATH=/path/to/hyperliquid-python-sdk \
  python packages/hyperliquid/src/fixtures/signing/generate.py \
  /path/to/hyperliquid-python-sdk
```
